Bản đồ A-Z

Nguyên tắc chính: không nhảy từ prompt thô sang Pencil hoặc code. Mọi thứ phải đi qua artifact, validation và QA.

01

Chọn mode

  • fast: card, modal, empty state, ý tưởng nhỏ.
  • standard: màn hình đầy đủ thông thường.
  • strict: checkout, auth, pricing, onboarding, handoff, contract hoặc codegen.
02

Tạo run folder

  • Tạo slug ổn định, ví dụ: login_screen.
  • Mọi artifact nằm trong artifacts/{slug}/.
  • Tạo screen_run.yaml trước để tracking mode, gate, Pencil frame và next step.
03

Chuẩn hóa prompt

  • Biến yêu cầu thô thành goal, audience, screen type, content, state và assumption.
  • Fast mode có thể dùng prompt.md.
  • Standard/strict dùng normalized_brief.json.
04

Lập UX plan

  • Xác định hierarchy: dominant content, secondary content, CTA.
  • Liệt kê states: default, loading, empty, error, disabled, validation.
  • Quy định overflow cho title, label, CTA và content dài.
05

Định nghĩa visual system

  • Chọn tone, density, typography, color, spacing, component style.
  • Không để output generic hoặc chỉ là card/block rỗng.
  • Style phải phục vụ domain, không chỉ trang trí.
06

Tạo design spec

  • design_spec.json là source of truth trước Pencil.
  • design_spec.summary.md mô tả hierarchy và component anatomy.
  • Validate bằng python3 scripts/validate_screen.py artifacts/{slug}.
07

Render Pencil

  • Chỉ render từ design_spec.json, không render từ raw prompt.
  • Dùng một file chung: pencil/screen_design.pen.
  • Append frame mới, không xóa frame cũ nếu user không yêu cầu.
08

QA, handoff, codegen

  • QA chấm business fit, UX clarity, visual hierarchy, consistency, accessibility, prompt fidelity.
  • Strict mode cần handoff.md, contract.md, fidelity_review.md.
  • Codegen Flutter chỉ chạy sau khi handoff/contract hợp lệ.

Lộ trình học

Học theo 4 chặng. Mỗi chặng kết thúc bằng một output cụ thể để tránh chỉ đọc quy trình mà không tự chạy được.

W1

Nắm pipeline

  • Hiểu 3 mode: fast, standard, strict và khi nào phải dùng từng mode.
  • Tập phân tích prompt thành goal, audience, screen type, state, assumption.
  • Output cuối tuần: 3 file prompt.md cho card, modal và full screen.
W2

Spec hóa màn hình

  • Viết normalized_brief.json, ux_plan.json, visual_system.json.
  • Tập mô tả component anatomy, hierarchy, CTA và overflow rule.
  • Output cuối tuần: 1 bộ standard artifacts cho dashboard hoặc form.
W3

Render và QA

  • Render Pencil từ design_spec.json, không render từ raw prompt.
  • Chạy layout/screenshot check và viết design_qa.md.
  • Output cuối tuần: 1 screen pass UX clarity, visual hierarchy và prompt fidelity.
W4

Strict handoff

  • Làm một màn hình critical: checkout, auth, onboarding hoặc pricing.
  • Freeze handoff.md, tạo contract.md và review fidelity.
  • Output cuối tuần: strict package đủ để codegen hoặc bàn giao developer.

Ví dụ thực hành

Các bài dưới đây tăng dần độ khó. Mỗi bài có prompt mẫu, mode đề xuất và artifact cần nộp.

01

Empty state học tập

Prompt: “Tạo empty state cho app học tiếng Anh khi người dùng chưa có flashcard nào.”

  • Mode: fast.
  • Focus: hierarchy, CTA tạo flashcard đầu tiên, illustration placeholder không generic.
  • Nộp: prompt.md, design_spec.json, design_qa.md.
02

Dashboard tiến độ

Prompt: “Thiết kế dashboard theo dõi tiến độ học tiếng Nhật N5-N2, có kanji, grammar, listening và mock test.”

  • Mode: standard.
  • Focus: data density, scanning, state empty/loading, card không lồng card.
  • Nộp: normalized brief, UX plan, visual system, spec, QA, revision log.
03

Form nhập nguồn cào

Prompt: “Tạo màn nhập nguồn học liệu để lưu URL, provider, license note, trust level và course mapping.”

  • Mode: standard.
  • Focus: form anatomy, validation, disabled state, error copy, data contract.
  • Nộp: design spec có đầy đủ field, validation rule và overflow rule.
04

Checkout khóa học

Prompt: “Thiết kế checkout mua khóa Vibe design, có coupon, billing info, order summary và confirm payment.”

  • Mode: strict.
  • Focus: accessibility, validation, trust, review gate, no hidden cost.
  • Nộp: full standard artifacts + handoff, contract, fidelity review.
05

Mobile onboarding

Prompt: “Tạo onboarding mobile cho người mới chọn mục tiêu: tiếng Anh, tiếng Nhật, Agentic AI hoặc Vibe design.”

  • Mode: strict nếu có codegen, standard nếu chỉ render design.
  • Focus: one-screen scope, segmented control, primary CTA, selected/disabled states.
  • Nộp: design spec có viewport mobile và state coverage.
06

QA revision drill

Prompt: “Review một screen bị generic, thiếu state và CTA không rõ; sửa upstream artifact đúng chỗ.”

  • Mode: standard.
  • Focus: phát hiện lỗi thuộc intent, UX, visual, component hay renderer.
  • Nộp: design_qa.md và revision_log.md giải thích sửa layer nào.

Cổng chất lượng

Nếu QA fail, sửa đúng artifact upstream gây lỗi. Không vá downstream để che lỗi gốc.

8+

UX clarity

Màn hình phải rõ mục tiêu, luồng thao tác và hierarchy. User biết phải nhìn đâu và làm gì tiếp.

8+

Prompt fidelity

Output phải bám đúng scope prompt. Không tự thêm flow, section hoặc chức năng ngoài yêu cầu.

7+

Accessibility

Text readable, button đủ rõ, state đầy đủ, overflow không phá layout.

Checklist chạy thật

Dùng checklist này trước khi render Pencil hoặc codegen. Nếu có điểm chưa đạt, quay lại artifact tương ứng.

✓Đã chọn mode và tạo screen_run.yaml.
✓Prompt đã được normalize thành brief rõ scope.
✓UX plan có hierarchy, state và overflow rule.
✓Visual system đủ cụ thể, không generic.
✓design_spec.json validate pass.
✓Pencil render chỉ dùng design spec.
✓QA đạt threshold: fidelity 8, UX 8, hierarchy 8, accessibility 7.
✓Strict/codegen có handoff, contract và fidelity review.
