Sơ đồ vận hành

Mục tiêu không phải thay thế team IT, mà giảm thời gian triage, gom đúng ngữ cảnh và giữ người thật ở các điểm quyết định quan trọng.

01

Intake Agent

Nhận ticket từ Slack, Jira, email. Chuẩn hóa title, severity, affected service, user impact và dữ liệu còn thiếu.

02

Runbook Agent

Tìm runbook, incident cũ, dashboard liên quan. Chỉ trả lời dựa trên nguồn có version và owner rõ ràng.

03

Action Agent

Tạo draft PR, mở task, gợi ý rollback, chuẩn bị lệnh kiểm tra. Không deploy, restart hoặc gửi thông báo thật nếu chưa được duyệt.

04

Reviewer Agent

Kiểm tra risk, SLA, quyền hạn, PII, command nguy hiểm và mức tự tin trước khi trình người duyệt.

Sprint lab 5 ngày

Mỗi ngày tạo một artifact nhỏ. Cuối lab có thể demo agent xử lý incident giả lập từ intake tới approval.

D1

Map workflow

  • Chọn 3 loại ticket thường gặp: bug, access request, incident.
  • Vẽ input, output, owner, SLA và điểm cần người duyệt.
  • Định nghĩa trạng thái: new, investigating, waiting_approval, resolved.
D2

Thiết kế tools

  • Định nghĩa schema cho search_ticket, search_runbook, get_logs, create_task.
  • Mô tả lỗi dự kiến: not_found, permission_denied, stale_data.
  • Tạo mock response để test agent loop.
D3

Memory và RAG

  • Tạo 8 runbook ngắn cho service quan trọng.
  • Gắn metadata: service, owner, version, last_reviewed.
  • Bắt agent trích nguồn khi đề xuất action.
D4

Guardrails

  • Liệt kê allowed, approval_required và blocked actions.
  • Thêm policy cho secrets, PII, production command.
  • Viết approval payload để IT Lead duyệt.
D5

Eval và demo

  • Tạo 12 test cases cho ticket thật hoặc giả lập.
  • Chấm task success, groundedness, tool accuracy, approval compliance.
  • Demo một incident end-to-end với trace rõ từng bước.

IT Ops Agent

  1. Nhận ticket, xác định severity, service, user impact và dữ liệu thiếu.
  2. Tìm runbook và incident cũ, kèm nguồn rõ ràng.
  3. Đề xuất plan xử lý, nhưng không tự chạy action production.
  4. Tạo approval payload cho IT Lead khi cần deploy, restart, rollback hoặc gửi thông báo khách hàng.
  5. Ghi trace gồm input, tool call, observation, decision và evaluator note.
